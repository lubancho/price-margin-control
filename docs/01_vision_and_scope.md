# 01. Паспорт проекта, контекст и границы

> **Статус документа:** черновик этапа 1 (проектирование). Код ещё не написан.
> Все данные в проекте — **синтетические**. Никакие цифры не являются показателями реальной компании.

## 1. Паспорт проекта

| Поле | Значение |
|---|---|
| Название | Контроль цен и маржинальности торговой сети |
| Технический адрес репозитория | `price-margin-control` |
| Тип | Самостоятельный учебно-практический проект для портфолио |
| Бизнес-контекст | Сеть точек формата «суши-маркет» (роллы, суши, наборы), Омск и область. Модель вымышленная |
| Цель | Прототип системы поддержки решений по ценообразованию: показатели маржинальности, рекомендуемые цены с объяснением, выявление нарушений правил |
| Чего система **не делает** | Не меняет реальные цены в кассовой/торговой системе; не прогнозирует спрос машинным обучением; не является защищённой системой с разграничением доступа |
| Пользователи | Аналитик, руководитель сети, операционный менеджер |
| Стек | Python 3.12, PostgreSQL 16, Streamlit, Plotly, Pandas, Pytest, Ruff, Docker Compose, GitHub Actions |
| Связанный проект | `assortment-writeoff-analytics` (проект №2) — тот же справочник точек и товаров |

## 2. Бизнес-контекст простыми словами

Сеть продаёт готовую еду. Себестоимость ингредиентов (рыба, рис, нори, сыр) меняется часто, а цены на витрине пересматривают редко и вручную. Из-за этого часть позиций незаметно теряет маржу. Ещё одна проблема — разные цены на один товар в разных точках без понятной причины и ошибки в исходных данных (нулевая себестоимость, пропавшая цена).

Система отвечает на три вопроса:
1. **Где сейчас теряется маржа?** — показатели и предупреждения.
2. **Какой должна быть цена по нашим правилам?** — рекомендация с объяснением.
3. **Что будет, если применить рекомендации?** — сценарный расчёт с явными допущениями.

## 3. Цели и показатели успеха

| ID | Цель | Как проверяем (для прототипа) |
|---|---|---|
| G-01 | Видеть товарные предложения ниже минимальной маржи | Экран «Анализ цен» показывает их с фильтром; доля считается по методике М-06 |
| G-02 | Получать рекомендуемую цену с объяснением | У каждой рекомендации есть код и текст причины, версия правил, идентификатор запуска |
| G-03 | Не пропускать ошибки данных | Все заложенные в генератор ошибки находятся проверками качества (тест на полноту) |
| G-04 | Оценить эффект изменения цен до решения | Экран «Сценарии»: до/после, допущения о спросе видны на экране |
| G-05 | Воспроизводимость | Повторный запуск на тех же данных и правилах даёт тот же результат и не плодит дубли |

| Роль | Интерес | Что получает | Влияние на решения |
|---|---|---|---|

## 5. Границы (scope)

**Входит в версию 1:**
- генерация демо-данных (15 точек, 150 товаров, 5 категорий, 90 дней) с заведомыми ошибками;
- загрузка в «сырой» слой, проверки качества, перенос валидных данных в основной слой;
- расчёт метрик М-01…М-06;
- расчёт рекомендуемых цен по правилам (без ML);
- предупреждения трёх уровней с защитой от дублей;
- сценарный анализ при фиксированном спросе или явно заданном коэффициенте;
- согласование/отклонение рекомендаций в интерфейсе (только запись статуса в БД);
- журнал запусков, изменений правил, решений;
- экспорт CSV и Excel.

**Не входит:**
- интеграция с реальными кассовыми системами и 1С;
- изменение цен в торговой системе;
- авторизация и разграничение прав (есть только переключатель роли — это **не** защита);
- оценка эластичности спроса по данным;
- операционная прибыль (аренда, ФОТ и т. п.) — считаем только валовую.

## 6. Ключевые допущения

| ID | Допущение | Почему так |
|---|---|---|
| A-01 | Себестоимость единицы одинакова во всех точках сети и меняется версиями во времени | Типично для сети с единой закупкой и техкартами; упрощает модель. Расширяется полем `store_id` в будущем |
| A-02 | Возврат отменяет и выручку, и себестоимость проданной единицы | Возвращённая продукция учитывается не в валовой марже, а в списаниях (проект №2) |
| A-03 | Отменённая операция не участвует ни в одном показателе | Отмена = операции не было |
| A-04 | Себестоимость продажи берётся по версии, действовавшей на дату продажи | Иначе история маржи «переписывается» при каждом изменении себестоимости |
| A-05 | Прогноз — это сценарий, а не предсказание | Нет достоверной оценки эластичности |
| A-06 | Снижение цены система по умолчанию не рекомендует | Бизнес-правило сети; включается параметром `allow_decrease` |

## 8. Названия и оформление

Используется нейтральное название «Сеть суши-маркетов (демо)». Логотипы, фирменные цвета и названия реальной сети не используются; точки называются условно («Омск — Левобережье-1»), без реальных адресов.
