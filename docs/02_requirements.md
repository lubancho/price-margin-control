# 02. Требования, сценарии, критерии приёмки и трассировка

Идентификаторы: `FR` — функциональные, `NFR` — нефункциональные, `BR` — бизнес-правила, `UC` — сценарии, `AC` — критерии приёмки, `TC` — тест-кейсы. Статус любого требования до реализации — **«Не готово»**.

## 1. Бизнес-правила

| ID | Правило |
|---|---|
| BR-01 | Рекомендуемая цена = себестоимость / (1 − целевая маржа), целевая маржа ∈ [0; 1) |
| BR-02 | Минимальная маржа ≤ целевой; рекомендуемая цена не может дать маржу ниже минимальной |
| BR-03 | Изменение цены за один пересмотр не превышает `max_change` от текущей |
| BR-04 | Цена кратна шагу округления; округление вверх по умолчанию |
| BR-05 | Если BR-02 и BR-03 несовместимы — статус CONFLICT, цена не предлагается, ручное рассмотрение |
| BR-06 | Снижение цены не рекомендуется, если правило это не разрешает |
| BR-07 | Для товаров в действующей промоакции рекомендация откладывается (ON_HOLD) |
| BR-08 | Применяется самое конкретное правило: товар → категория → точка → сеть |
| BR-09 | Использованный набор правил не изменяется; изменение = новая версия |
| BR-10 | Себестоимость продажи — версия на дату продажи |
| BR-11 | Отменённые операции не учитываются; возвраты вычитаются из выручки, количества и себестоимости |
| BR-12 | Система не изменяет цены во внешних системах |
| BR-13 | Открытое предупреждение с тем же ключом не создаётся повторно |

## 4. Пользовательские сценарии

### UC-01. Аналитик запускает пересчёт цен
1. Аналитик открывает «Анализ цен», выбирает дату и нажимает «Рассчитать».
2. Система проверяет ключ идемпотентности. Если такой запуск уже есть — показывает его и предлагает «Пересчитать принудительно».
3. Система рассчитывает рекомендации, сохраняет их, формирует предупреждения, пишет событие в журнал.
4. Аналитик видит сводку: предложено N, без изменений M, конфликтов K, заблокировано B.

**Исключения:** нет глобального правила → запуск `failed`, понятное сообщение; ошибка БД → запуск `failed`, рекомендации не сохраняются частично (одна транзакция).

### UC-02. Руководитель согласует рекомендации
1. Выбирает роль «Руководитель», фильтрует `PROPOSED` и `CONFLICT`.
2. Отмечает строки, нажимает «Согласовать» или «Отклонить»; для CONFLICT вводит цену вручную.
3. Статус и автор решения сохраняются, событие пишется в журнал.

**Исключение:** роль «Операционный менеджер» не видит кнопок согласования (ограничение интерфейса, не защита).

### UC-03. Операционный менеджер разбирает отклонения своей точки
Фильтрует «Анализ цен» и «Предупреждения» по точке, открывает карточку проблемного предложения: история цены и себестоимости, маржа, правило, причина.

### UC-04. Аналитик сравнивает сценарии
Меняет целевую маржу / лимит / `e` в форме (без сохранения правил), видит до/после и допущения; при необходимости сохраняет как новую версию правил.

### UC-05. Экспорт
Выбирает таблицу и формат, получает файл с пометкой о синтетических данных и параметрами отбора.

## 5. Критерии приёмки

| ID | Критерий | Требования |
|---|---|---|
| AC-01 | Два запуска генератора с одним seed дают побайтно одинаковые CSV | FR-01 |
| AC-02 | Все ошибки E-01…E-09 из манифеста найдены проверками качества или предупреждениями | FR-02, FR-07 |
| AC-03 | Выручка, валовая прибыль и маржинальность за период совпадают в SQL и Python до копейки | FR-03, NFR-04 |
| AC-04 | Разобранный пример из документа 04 даёт 270 ₽, PROPOSED, флаг LIMITED_UP | FR-04 |
| AC-05 | Пример конфликта даёт CONFLICT и пустую рекомендуемую цену | FR-04, BR-05 |
| AC-06 | Повторный запуск без изменений не создаёт новых запусков, рекомендаций и алертов | FR-06, FR-07 |
| AC-07 | Принудительный пересчёт переводит старые PROPOSED в SUPERSEDED | FR-06 |
| AC-08 | Набор правил, использованный в расчёте, нельзя изменить (ошибка БД) | FR-09, BR-09 |
| AC-09 | Решение по рекомендации видно в «Истории» с ролью и временем | FR-10, FR-12 |
| AC-10 | Экран сценариев показывает блок допущений при любых параметрах | FR-11 |
| AC-11 | XLSX открывается в Excel, суммы — числа, даты — даты | FR-13 |
| AC-12 | `docker compose up` из чистого клона поднимает приложение без ручных шагов | NFR-01 |

## 6. Тест-кейсы и трассировка

Номера соответствуют пп. ТЗ §17. Уровень: U — модульный, I — интеграционный с PostgreSQL, E — сквозной сценарий.

| ID | Проверка | Входные данные | Ожидаемый результат | Уровень | Требования |
|---|---|---|---|---|---|
| TC-01 | Расчёт маржи | цена 200, себест. 120 | 0,40 | U | FR-03 |
| TC-02 | Маржа ≠ наценка | цена 200, себест. 100 | маржа 0,50; наценка 1,00 | U | FR-03 |
| TC-03 | Нулевая себестоимость | C = 0 | BLOCKED, INVALID_COST; наценка None | U | FR-04, BR-01 |
| TC-04 | Отрицательная себестоимость | C = −10 | BLOCKED, INVALID_COST; в `core` не попадает | U, I | FR-02, FR-04 |
| TC-05 | Нет текущей цены | P0 = None | BLOCKED, NO_CURRENT_PRICE; алерт PRICE_UNDETERMINED | U | FR-04, FR-07 |
| TC-06 | Целевая маржа 100% | mt = 1 | ошибка валидации правила; INSERT в БД отклонён CHECK | U, I | BR-01 |
| TC-07 | Маржа вне границ | mt = −0,1; 1,5; mmin > mt | ошибка валидации | U | BR-01, BR-02 |
| TC-08 | Округление | 277,09 при шаге 10: up/nearest/down | 280 / 280 / 270 | U | BR-04 |
| TC-09 | Конфликт ограничений | пример конфликта из док. 04 | CONFLICT, цена None | U | BR-05 |
| TC-10 | Изменение сверх лимита | разобранный пример | 270, LIMITED_UP | U | BR-03 |
| TC-11 | Дубли данных | 50 дублей в `raw.sale_line` | в `core` 0 дублей, 50 записей DUPLICATE | I | FR-02 |
| TC-12 | Повторный запуск | два запуска подряд | 1 запуск, число рекомендаций и алертов не изменилось | I | FR-06, FR-07 |
| TC-13 | Формирование предупреждений | данные E-02…E-09 | ожидаемые коды алертов для каждой ошибки | I | FR-07 |
| TC-14 | Сохранение истории | расчёт + согласование | события RUN_COMPLETED и RECOMMENDATION_APPROVED в журнале | I | FR-10, FR-12 |
| TC-15 | Согласованность SQL/Python | весь демо-набор | итоги совпадают до копейки | I | NFR-04 |
| TC-16 | Возвраты и отмены | sale 2 шт, return 1 шт, cancelled 5 шт | количество 1, выручка за 1 шт | U, I | BR-11 |
| TC-17 | Себестоимость на дату | смена версии в середине периода | каждая продажа — по своей версии | I | BR-10 |
| TC-18 | Приоритет правил | правила сети, категории, товара | применено правило товара | U | BR-08 |
| TC-19 | Блокировка набора правил | UPDATE использованного правила | ошибка БД | I | BR-09 |
| TC-20 | Запрет снижения | маржа выше целевой | NO_CHANGE | U | BR-06 |
| TC-21 | Промо | товар в действующей акции | ON_HOLD | U | BR-07 |
| TC-22 | Детерминированность генератора | два запуска с seed | одинаковые файлы | U | FR-01 |
| TC-23 | Полнота поиска ошибок | манифест генератора | все E-коды найдены | I | FR-02, FR-07 |
| TC-24 | Экраны открываются | Streamlit AppTest по каждому экрану | без исключений | E | FR-15 |
| TC-25 | Экспорт | XLSX/CSV | типы сохранены, есть пометка о демо-данных | I | FR-13 |

Фактические результаты тестов будут добавлены после их выполнения (этап 5). До этого статус всех TC — **«Не проверено»**.
